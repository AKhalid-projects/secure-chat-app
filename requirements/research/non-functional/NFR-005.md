# NFR-005: Client credential and token handling

The Secure Chat Application shall store CometChat application credentials and rely on device push tokens in client-side storage and memory subject to platform APIs, and shall expose push provider identifiers for registration with CometChat. Category: **security**; priority: **High**. This requirement documents **what the prototype actually does** rather than prescribing an ideal enterprise key management regime.

Async storage and embedded constants appear in the evidence trail; the undergraduate report should treat production hardening as a **future improvement** rather than as a claim satisfied by the sample alone.

Confidence is **explicit** where storage and constants are visible. Verification is inspection-led and may include threat-awareness discussion without overstating empirical penetration testing.

**FR-002** and **FR-015** are the main functional touchpoints; **FR-017** should be read alongside this requirement when discussing privacy claims.
