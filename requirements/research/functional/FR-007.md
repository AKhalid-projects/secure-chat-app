# FR-007: Conversations and messaging

The Secure Chat Application shall provide access to conversation lists and real-time messaging sessions for one-to-one and group contexts using CometChat UIKit components integrated into application screens. Priority is **High**; domain is **messaging**. This requirement captures the central user-facing purpose discussed in workshops: dependable exchange of messages in peer and group settings.

Implementation composes vendor message lists and composers with navigation parameters that identify users or groups, sometimes via serialisable identifiers resolved after navigation. A vendor patch guards against edge cases where conversation context is momentarily incomplete, which is documented as maintainability-related evidence rather than as a separate functional obligation.

Repository evidence includes conversation and message screen modules and the referenced patch. Confidence is **explicit** for core messaging surfaces. Verification relies on manual or device-based exercise of send and receive paths, acknowledging that full backend semantics lie outside the client repository.

**FR-008**, **FR-009**, and **FR-017** relate to threads, search, and privacy messaging layered on the messaging experience; **NFR-003** references vendor adaptation.
