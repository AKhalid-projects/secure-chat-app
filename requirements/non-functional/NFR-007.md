# NFR-007: Internationalization support

## 1. Requirement Statement

The Secure Chat Application shall integrate CometChat’s internationalization provider so that UI strings supplied by the UIKit can be translated according to CometChat i18n conventions.

## 2. Requirement Type

- Non-Functional Requirement

## 3. NFR Category

- Localization

## 4. Description

`CometChatI18nProvider` wraps the navigation tree in `App.tsx`. Tab labels use `useCometChatTranslation` (`BottomTabNavigator`). Custom screens may still contain hard-coded English (e.g., encryption copy).

## 5. Rationale

Supports multi-locale deployments without rewriting UIKit internals.

## 6. Quality Scenario

- **Source**: User device locale differs from English.
- **Stimulus**: UIKit surfaces labels.
- **Artifact**: CometChat components.
- **Environment**: Localized resource packs from vendor.
- **Response**: Translated strings where provided by UIKit.
- **Response Measure**: UIKit strings follow locale; custom strings may remain English.

## 7. Measurable Criteria

- Provider present in render tree; translation hook used in tabs.

## 8. Applicability

- CometChat UIKit components; partial coverage for custom components.

## 9. Constraints / Policies

- Full localization requires auditing custom text (encryption modal, toasts).

## 10. Evidence from Repository

- `App.tsx` (`CometChatI18nProvider`)
- `src/navigation/BottomTabNavigator.tsx` (`useCometChatTranslation`)

## 11. Source Confidence

- **Explicit** — Provider and hooks used.

## 12. Verification Approach

- Change device language; inspect UIKit labels vs. custom strings (manual).

## 13. Risks if Unmet

- Mixed-language UX if only vendor strings translate.
