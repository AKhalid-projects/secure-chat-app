# NFR-011: Third-party service integration

## 1. Requirement Statement

The Secure Chat Application shall depend on CometChat cloud services for messaging and calling semantics and on Firebase Cloud Messaging (via React Native Firebase) for push transport on Android, with Apple push services for iOS, such that availability and behavior of those services directly bound application capabilities.

## 2. Requirement Type

- Non-Functional Requirement

## 3. NFR Category

- Integrability

## 4. Description

The client embeds CometChat SDKs and uses Firebase messaging modules. There is no alternate backend abstraction layer in the sample; failures or quota issues in CometChat or Firebase manifest as user-visible errors or missing notifications.

## 5. Rationale

Managed services accelerate feature delivery but create external dependencies.

## 6. Quality Scenario

- **Source**: CometChat API outage.
- **Stimulus**: Message send.
- **Artifact**: Chat client.
- **Environment**: Production.
- **Response**: Operations fail or queue per SDK.
- **Response Measure**: Error surfaced in UI or logs; no local offline-first DB evidenced.

## 7. Measurable Criteria

- `package.json` lists `@cometchat/*` and `@react-native-firebase/messaging`; README documents dashboard configuration.

## 8. Applicability

- All real-time and push features.

## 9. Constraints / Policies

- Data residency and compliance follow CometChat/Firebase terms; not encoded in app.

## 10. Evidence from Repository

- `package.json`
- `README.md`
- `App.tsx`, `index.js` (Firebase messaging imports)

## 11. Source Confidence

- **Explicit** — Dependencies and integration imports are clear.

## 12. Verification Approach

- Contract tests against CometChat sandbox; Firebase console message tests.

## 13. Risks if Unmet

- Vendor lock-in, cost exposure, and outage correlation with provider SLAs.
