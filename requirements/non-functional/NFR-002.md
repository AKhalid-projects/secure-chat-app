# NFR-002: Error containment

## 1. Requirement Statement

The Secure Chat Application shall limit the blast radius of unhandled JavaScript errors by providing a React error boundary at the root and global error handlers for fatal and promise rejections at startup.

## 2. Requirement Type

- Non-Functional Requirement

## 3. NFR Category

- Reliability

## 4. Description

`AppErrorBoundary` wraps the app tree. `index.js` overrides `global.ErrorUtils` handler and logs unhandled promise rejections. This improves perceived stability by showing a fallback UI instead of a blank crash for render errors.

## 5. Rationale

Mobile chat apps must avoid hard crashes where possible; graceful degradation supports usability and debugging.

## 6. Quality Scenario

- **Source**: Runtime fault in a child component.
- **Stimulus**: Uncaught render error.
- **Artifact**: React component tree.
- **Environment**: Production or dev build.
- **Response**: Error boundary renders fallback with retry.
- **Response Measure**: User sees fallback screen, not white screen of death.

## 7. Measurable Criteria

- Presence of `componentDidCatch` and fallback render path in `AppErrorBoundary.tsx`.
- Global handler installed in `index.js`.

## 8. Applicability

- JavaScript layer; native crashes are out of scope.

## 9. Constraints / Policies

- Error reporting to external services is not implemented (console only).

## 10. Evidence from Repository

- `AppErrorBoundary.tsx`
- `index.js` (ErrorUtils, unhandledRejection)

## 11. Source Confidence

- **Explicit** — Code implements containment.

## 12. Verification Approach

- Code review; optional fault injection in dev (manual test).

## 13. Risks if Unmet

- Poor user experience and harder diagnosis of field failures.
