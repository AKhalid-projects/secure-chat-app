# FR-017: Encryption and privacy messaging UX

## 1. Requirement Statement

The Secure Chat Application shall display an encryption notice banner and an informational modal that explain end-to-end encryption and privacy of chats and calls in accessible language, including optional external reference via a learn-more link.

## 2. Requirement Type

- Functional Requirement

## 3. Module / Domain

- Privacy
- User experience

## 4. Description

`EncryptionNoticeBanner` appears on the message screen; tapping opens `EncryptionInfoModal`, which lists categories of protected content and explanatory copy. This is **user-facing assurance UX**; it does not implement a custom cryptographic protocol in application code.

## 5. Rationale

Aligns user expectations with marketing/security claims and supports trust in the Secure Chat Application branding.

## 6. Inputs

- User taps banner or modal close actions.

## 7. Processing / Behavior

1. Render banner with lock icon and themed styles.
2. Show modal with SVG illustration and bullet list.
3. Optional `learnMoreUrl` opens via `Linking` (default `#` in code).

## 8. Outputs

- User has read privacy explanation; modal visibility toggles.

## 9. Preconditions

- User is on a screen that mounts the banner (Messages).

## 10. Postconditions

- Modal closed returns to chat view.

## 11. Error Handling / Exceptions

- BackHandler on Android closes modal.

## 12. Business Rules / Constraints

- Copy is static in components; not localized beyond CometChat i18n for other UI.

## 13. Dependencies

- `react-native-svg`, `@cometchat/chat-uikit-react-native` `useTheme`.

## 14. Evidence from Repository

- `src/components/conversations/EncryptionNoticeBanner.tsx`
- `src/components/conversations/EncryptionInfoModal.tsx`
- `src/components/conversations/screens/Messages.tsx` (imports and placement)

## 15. Source Confidence

- **Explicit** — Components and integration exist.

## 16. Acceptance Criteria

- Given Messages screen loaded,
- When the view renders,
- Then the encryption banner is visible per implementation.

- Given the user taps the banner,
- When the modal opens,
- Then explanatory text and illustration are shown.

- Given the user closes the modal,
- When onClose fires,
- Then the modal is not visible.
