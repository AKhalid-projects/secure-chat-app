# NFR-009: Native capability declarations

## 1. Requirement Statement

The Secure Chat Application shall declare platform permissions, background execution modes, and edge-to-edge UI settings required for camera, microphone, notifications, calls, and configuration screens in iOS and Android manifests via Expo configuration.

## 2. Requirement Type

- Non-Functional Requirement

## 3. NFR Category

- Compatibility

## 4. Description

`app.json` includes `NSCameraUsageDescription`, `NSMicrophoneUsageDescription`, `UIBackgroundModes` (`remote-notification`, `voip`), Android permissions (`INTERNET`, `CAMERA`, `RECORD_AUDIO`, `POST_NOTIFICATIONS`, `FOREGROUND_SERVICE`, etc.), `edgeToEdgeEnabled`, and `configChanges` for keyboard/orientation. These enable OS-level consent and background behavior for messaging and calls.

## 5. Rationale

Without correct declarations, App Store/Play compliance and runtime permission flows fail.

## 6. Quality Scenario

- **Source**: User initiates video call or VoIP push arrives.
- **Stimulus**: OS permission or background wake.
- **Artifact**: Native shell generated from Expo config.
- **Environment**: Physical device.
- **Response**: System prompts or background handlers allowed.
- **Response Measure**: Permission dialogs appear; VoIP/call features function per platform rules.

## 7. Measurable Criteria

- `app.json` lists required `infoPlist` and `android.permissions` entries.

## 8. Applicability

- Native layers; QR scanner, calls, notifications.

## 9. Constraints / Policies

- Store review may require additional privacy manifests (iOS privacy files may exist in native tree when generated).

## 10. Evidence from Repository

- `app.json`

## 11. Source Confidence

- **Explicit** — Expo config documents capabilities.

## 12. Verification Approach

- Inspect `app.json`; validate on device that permissions align with features used.

## 13. Risks if Unmet

- Rejected store builds or broken calls/notifications in production.
