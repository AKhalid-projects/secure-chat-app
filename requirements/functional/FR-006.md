# FR-006: Application navigation structure

## 1. Requirement Statement

The Secure Chat Application shall provide a stack-based navigator for authentication and feature screens and a bottom tab navigator for primary areas, with dynamic tab ordering based on configuration and an imperative navigation service that supports deferred navigation when the container is not ready.

## 2. Requirement Type

- Functional Requirement

## 3. Module / Domain

- Navigation

## 4. Description

`NavigationContainer` wraps a stack: `AppCredentials`, `SampleUser`, `BottomTabNavigator`, plus screens for conversations, messages, threads, search, user/group info, moderation, calls, QR, etc. Initial route depends on login and credential validity. `BottomTabNavigator` maps `config.settings.layout.tabs` to `Chats`, `Calls`, `Users`, `Groups` screens. `NavigationService` provides `navigate` and `processPendingNavigation` for cases where navigation ref is not ready.

## 5. Rationale

Clear separation between auth/bootstrap and main app; deferred navigation supports push notification entry before the tree mounts.

## 6. Inputs

- `isLoggedIn`, `hasValidAppCredentials` from `App.tsx`.
- Tab keys from `useConfig`.

## 7. Processing / Behavior

1. Choose stack initial route.
2. Render tab screens dynamically.
3. Queue or execute navigation via `navigationRef`.

## 8. Outputs

- Visible screen transitions; stack state updates.

## 9. Preconditions

- `NavigationContainer` mounted; ref attached.

## 10. Postconditions

- User can reach all registered routes from valid entry points.

## 11. Error Handling / Exceptions

- Invalid routes avoided by typed param lists; pending nav processed on `onReady`.

## 12. Business Rules / Constraints

- Tab `name` must match `BottomTabParamList` keys used in icons map.

## 13. Dependencies

- `@react-navigation/native`, `@react-navigation/stack`, `@react-navigation/bottom-tabs`.

## 15. Source Confidence

- **Explicit** — Navigation graph is fully defined in code.

## 16. Acceptance Criteria

- Given valid credentials and no session,
- When the app starts,
- Then `SampleUser` or `AppCredentials` appears per `RootStackNavigator` rules.

- Given config tabs `chats`, `calls`,
- When the tab navigator renders,
- Then only those tabs are rendered.

- Given `navigate` is called before `onReady`,
- When the container becomes ready,
- Then `processPendingNavigation` applies the queued route.
