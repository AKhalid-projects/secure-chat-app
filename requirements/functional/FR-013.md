# FR-013: Incoming call handling

## 1. Requirement Statement

The Secure Chat Application shall detect incoming CometChat calls, present the incoming-call user interface, allow decline, and reject new incoming calls with a busy status when another call is already active.

## 2. Requirement Type

- Functional Requirement

## 3. Module / Domain

- Calls

## 4. Description

`App.tsx` registers `CometChat.addCallListener` with `onIncomingCallReceived`. If `CometChat.getActiveCall()` returns an active call, the app schedules `CometChat.rejectCall` with `CALL_STATUS.BUSY` after a short delay; otherwise it emits UI events to dismiss bottom sheets, stores the incoming call, and sets state so `CometChatIncomingCall` renders. Decline clears state; cancel/end listeners reset state.

## 5. Rationale

Prevents concurrent call confusion and matches expected telephony semantics.

## 6. Inputs

- Incoming `CometChat.Call` from SDK.
- Current active call state from SDK.

## 7. Processing / Behavior

1. On incoming, evaluate active call.
2. If busy, reject with BUSY; else show incoming UI.
3. On decline/cancel/end, clear refs and state.

## 8. Outputs

- User sees incoming overlay or remote party receives busy rejection.

## 9. Preconditions

- Call listener registered; user logged in.

## 10. Postconditions

- Call state consistent with accept/reject/end events.

## 11. Error Handling / Exceptions

- If `getActiveCall` throws, fallback path still shows incoming call.

## 12. Business Rules / Constraints

- Busy rejection delayed by timeout (implementation-specific).

## 13. Dependencies

- `CometChat.addCallListener`, `CometChatIncomingCall`, `CometChatUIEventHandler`.

## 14. Evidence from Repository

- `App.tsx` (call listener, `CometChatIncomingCall`)

## 15. Source Confidence

- **Explicit** — Logic is fully implemented in `App.tsx`.

## 16. Acceptance Criteria

- Given no active call,
- When an incoming call arrives,
- Then `CometChatIncomingCall` is shown with the call object.

- Given an active call exists,
- When another incoming call arrives,
- Then the second call is rejected with busy status.

- Given the user declines,
- When decline handler runs,
- Then incoming state clears.
