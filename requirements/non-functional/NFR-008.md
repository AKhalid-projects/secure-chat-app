# NFR-008: Technology stack compatibility

## 1. Requirement Statement

The Secure Chat Application shall declare and consume a fixed matrix of framework and library versions—including Expo, React Native, React, CometChat packages, Firebase modules, and native add-ons—such that builds remain reproducible within that matrix.

## 2. Requirement Type

- Non-Functional Requirement

## 3. NFR Category

- Compatibility

## 4. Description

`package.json` pins `expo ~54.0.12`, `react-native 0.81.4`, `react 19.1.0`, CometChat UIKit `5.2.10`, and numerous native dependencies (WebRTC, Vision Camera, etc.). Compatibility is **component-level**: upgrading one package may require coordinated upgrades.

## 5. Rationale

Chat, calls, and push stacks are sensitive to native ABI and JS API changes.

## 6. Quality Scenario

- **Source**: Maintainer updates a dependency.
- **Stimulus**: Major version bump.
- **Artifact**: Build pipeline.
- **Environment**: Developer machine / CI.
- **Response**: Build may fail until aligned versions found.
- **Response Measure**: Successful `npm install` and native build.

## 7. Measurable Criteria

- Single `package.json` / lockfile defines versions; README states Node 18+.

## 8. Applicability

- Entire dependency graph.

## 9. Constraints / Policies

- `react-native-callkeep` sourced from GitHub fork in manifest—special attention on updates.

## 10. Evidence from Repository

- `package.json`
- `package-lock.json`
- `README.md`

## 11. Source Confidence

- **Explicit** — Declared dependencies.

## 12. Verification Approach

- Clean install and native build; dependency audit tools optional.

## 13. Risks if Unmet

- Build failures, runtime crashes, or push/call regressions after drift.
