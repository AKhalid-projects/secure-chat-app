# NFR-003: Maintainability and vendor adaptation

## 1. Requirement Statement

The Secure Chat Application shall organize features into cohesive modules (navigation, screens, utils, config) and shall apply controlled patches to third-party UIKit sources where upstream defects affect stability.

## 2. Requirement Type

- Non-Functional Requirement

## 3. NFR Category

- Maintainability

## 4. Description

The `src/` tree separates concerns. `patch-package` runs on `postinstall` and modifies `CometChatMessageList` to avoid request builder errors when user/group is absent, with dependency array updates for `user`/`group`. This pattern trades pristine `node_modules` for predictable runtime behavior.

## 5. Rationale

Vendor SDKs evolve; local patches document known issues and reduce crash rates during upgrades.

## 6. Quality Scenario

- **Source**: SDK edge case with undefined conversation context.
- **Stimulus**: Message list mounts without user/group.
- **Artifact**: UIKit message list.
- **Environment**: Navigation race or partial state.
- **Response**: Patch short-circuits builder setup.
- **Response Measure**: No `setTypes` undefined crash.

## 7. Measurable Criteria

- `patches/` directory contains patch file; `package.json` has `postinstall: patch-package`.

## 8. Applicability

- `@cometchat/chat-uikit-react-native` specifically patched file.

## 9. Constraints / Policies

- Upgrading UIKit version requires regenerating or revalidating patches.
