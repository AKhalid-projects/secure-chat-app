# FR-005: QR configuration import

The Secure Chat Application shall capture QR codes using the device camera, retrieve builder configuration from a remote API when a code is scanned, persist the result to local storage, and update the global configuration store so that behaviour and styling reflect the imported settings. Priority is **Medium**; domain is **configuration**. This capability was discussed as an operational convenience for synchronising dashboard or builder output with the device without manual transcription.

The requirement presumes permission for camera access and network availability for retrieval. Persisted configuration must conform to structures accepted by the store initialisation logic so that subsequent launches honour imported settings. The feature sits alongside static JSON defaults and workshop-backed expectations that demonstrations should be reconfigurable with limited friction.

Evidence is located in the QR screen module and in shared storage keys used by the configuration store. Confidence is **explicit** where scanning, fetch, and persistence are implemented. Verification involves successful scan flows, storage inspection at an appropriate level of abstraction, and visible UI changes after import.

The requirement complements **FR-004**; **NFR-004** and **NFR-009** relate to configurability and native permission declarations respectively.
