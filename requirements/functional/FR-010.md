# FR-010: User directory and profiles

## 1. Requirement Statement

The Secure Chat Application shall present a list of users and detailed user information screens so that authenticated users can discover peers and open direct conversations or profile views.

## 2. Requirement Type

- Functional Requirement

## 3. Module / Domain

- User management

## 4. Description

`Users` screen lists CometChat users; selecting a user navigates to `Messages` with appropriate params. `UserInfo` displays profile details for a `CometChat.User` object. These screens integrate with UIKit avatar and styling.

## 5. Rationale

Directory and profiles are essential for social and enterprise chat adoption.

## 6. Inputs

- SDK user list and `CometChat.User` instances.

## 7. Processing / Behavior

1. Fetch or display users.
2. On selection, navigate to messaging.
3. From message context, open `UserInfo` when user navigates from header actions.

## 8. Outputs

- Navigation to chat or profile display.

## 9. Preconditions

- Logged-in user.

## 10. Postconditions

- Peer context is visible or conversation started.

## 11. Error Handling / Exceptions

- Loading/error states per screen implementation.

## 12. Business Rules / Constraints

- User visibility follows CometChat app subscription and permissions.

## 13. Dependencies

- CometChat SDK user APIs, UIKit components.

## 14. Evidence from Repository

- `src/components/users/Users.tsx`
- `src/components/conversations/screens/UserInfo.tsx`
- `src/navigation/RootStackNavigator.tsx`

## 15. Source Confidence

- **Explicit** — Screens registered in navigator.

## 16. Acceptance Criteria

- Given the Users tab,
- When the screen loads,
- Then users are listed and tappable to start a chat.

- Given navigation to UserInfo with a user object,
- When the screen renders,
- Then profile details for that user are shown.
