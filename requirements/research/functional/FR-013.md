# FR-013: Incoming call handling

The Secure Chat Application shall detect incoming CometChat calls, present the incoming-call user interface, allow decline, and reject new incoming calls with a busy status when another call is already active. Priority is **High**; domain is **calls**. Participants expected telephony-like behaviour: clear presentation of an incoming session and a sensible response when a line is already occupied.

Application-level listeners distinguish between acceptance paths and busy rejection. Vendor UI components participate in presentation; timing of rejection is implementation-specific but observable in the shell module.

Evidence is concentrated in the root application module alongside call listener registration. Confidence is **explicit**. Verification includes simulating concurrent incoming calls where feasible and observing decline and busy paths.

**FR-012** and **FR-014** complete the call story; **FR-016** intersects where call events interact with notification flows on some platforms.
