# FR-003: CometChat authentication and session bootstrap

## 1. Requirement Statement

The Secure Chat Application shall provide CometChat-native Sign In and Sign Up flows: users can sign in with UID and create accounts using CometChat `POST /users`, then enter the primary tabbed experience upon successful login.

## 2. Requirement Type

- Functional Requirement

## 3. Module / Domain

- Authentication

## 4. Description

After tenant credentials are configured, users can either:
- Sign in by entering a CometChat UID (SDK login), or
- Sign up by submitting `uid` and `name` (plus optional profile fields) through CometChat REST create-user API.
After successful authentication, the app resets navigation to `BottomTabNavigator`.

## 5. Rationale

This pattern keeps authentication aligned with CometChat-native requirements while enabling direct user creation without a custom backend.

## 6. Inputs

- CometChat UID for Sign In.
- For Sign Up: `uid`, `name`, and optional profile metadata fields.
- Preloaded CometChat SDK from successful init.

## 7. Processing / Behavior

1. User chooses Sign In or Sign Up.
2. Sign In: app calls `CometChatUIKit.login(uid)`.
3. Sign Up: app calls CometChat REST `POST /users` with required fields (`uid`, `name`) and optional fields.
4. After successful user creation, app signs in with created UID.
5. App navigates to `BottomTabNavigator` and resets navigation state.
6. On failure, app remains on auth flow and shows an error.

## 8. Outputs

- Active CometChat session for the authenticated UID.
- New CometChat user record when Sign Up succeeds.
- `loginSuccess` on CometChat login listener (see `App.tsx`).

## 9. Preconditions

- Valid app credentials and successful CometChat SDK init.

## 10. Postconditions

- User is signed in to CometChat; `userLoggedIn` updates via CometChat `LoginListener`.

## 11. Error Handling / Exceptions

- CometChat login failures show mapped user-facing messages.
- Logout failures are handled and the app falls back to login flow safely.

## 12. Business Rules / Constraints

- Sign In UID must exist in CometChat tenant.
- Sign Up must provide `uid` and `name`.
- App credentials (App ID, Auth Key, Region) must match the selected CometChat app.
- Full-access CometChat REST API key is required for Sign Up (create-user call).

## 13. Dependencies

- CometChat SDK/UIKit, CometChat REST API, and `navigationRef`.

## 16. Acceptance Criteria

- Given valid CometChat credentials and an existing UID,
- When the user signs in,
- Then CometChat session is created and app navigates to main tabs.

- Given valid create-user payload (`uid`, `name`) and a valid REST API key,
- When the user signs up,
- Then CometChat user is created and the app signs in to that UID.

- Given CometChat login fails,
- When the app receives the SDK error,
- Then the app remains in auth flow and displays an error prompt.
