# FR-003: UID-based user login

The Secure Chat Application shall authenticate end users by CometChat user identifier using the UIKit login API, and upon success shall navigate to the primary tabbed experience. Priority is **High**; domain is **authentication**. Interview themes included the need for a straightforward sign-in path suitable for multi-user testing without a bespoke identity provider implemented within the project.

The requirement expresses a deliberate architectural choice: session establishment is delegated to CometChat’s model, with the sample application providing user selection from prepared data or manual entry. Login success propagates through SDK listeners and resets navigation to the main tab container, which is consistent with expectations that communication features become available only after an authenticated session exists.

Repository evidence is found in the sample user screen and in login listener wiring in the application shell. Confidence is **explicit**. Verification consists of executing login with a valid identifier and confirming navigation to tabs, together with listener state consistent with logged-in status for downstream features such as push registration.

**FR-001** and **FR-002** are logical prerequisites; **FR-015** depends on login state for token registration behaviour.
