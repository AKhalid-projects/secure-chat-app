# FR-008: Thread replies

The Secure Chat Application shall support threaded conversations by navigating to a thread view for a parent message and displaying thread-scoped message history in context. Priority is **Medium**; domain is **messaging**. Interview feedback included everyday use of replies in team chat; the requirement is classified as **inferred** in the master index to reflect stronger reliance on vendor behaviour and navigation wiring than on a single explicit line of business logic.

Thread entry points connect message and search flows to a dedicated screen with parameters that preserve user or group context. The requirement is distinct from general messaging because it addresses reply streams anchored to parent messages rather than only the primary conversation timeline.

Evidence appears in the thread screen module and navigation type definitions. Verification should confirm navigation from parent messages and acceptable behaviour of the thread list under SDK rules.

**FR-007** and **FR-009** are adjacent; **FR-004** may gate thread-related flags in configuration.
