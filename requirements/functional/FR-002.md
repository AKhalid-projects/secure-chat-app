# FR-002: Application credentials lifecycle

## 1. Requirement Statement

The Secure Chat Application shall allow operators to enter CometChat application credentials, persist them locally, re-initialize the SDK with updated values, and route first-time users to credential entry when credentials are incomplete.

## 2. Requirement Type

- Functional Requirement

## 3. Module / Domain

- Authentication
- Bootstrap

## 4. Description

Users may configure `appId`, `authKey`, and `region` on a dedicated screen. Valid submissions are persisted to AsyncStorage under `appCredentials`, trigger `CometChatUIKit.init` with the new values, and advance navigation toward user selection/login. On cold start, the root navigator chooses **AppCredentials** when `hasValidAppCredentials` is false, **SampleUser** when credentials exist but no session, or main tabs when logged in—per `RootStackNavigator` and `App.tsx` logic.

## 5. Rationale

Multi-tenant demos and development builds require changing CometChat app credentials without rebuilding the binary; persistence avoids re-entry on every launch.

## 6. Inputs

- User-entered `appId`, `authKey`, `region` on the credentials screen.
- Existing `appCredentials` from AsyncStorage when the screen loads.

## 7. Processing / Behavior

1. Load and display stored credentials when present.
2. Validate non-empty fields on continue.
3. Save JSON to AsyncStorage `appCredentials`.
4. Call `CometChatUIKit.init` with saved values.
5. Navigate and reset stack to `SampleUser` for UID login.

## 8. Outputs

- Updated AsyncStorage record.
- Reinitialized CometChat SDK.
- Navigation to sample user selection.

## 9. Preconditions

- User reached the credentials screen (initial route when credentials invalid).

## 10. Postconditions

- Credentials stored; SDK matches stored values; user is directed to login.

## 11. Error Handling / Exceptions

- Toast messages for missing fields; `console.error` on save/init failure.

## 12. Business Rules / Constraints

- All three fields must be non-empty to proceed.

## 13. Dependencies

- `AsyncStorage`, `CometChatUIKit`, `AppConstants` (fallback in `App.tsx`).

## 14. Evidence from Repository

- `src/components/login/AppCredentials.tsx`
- `App.tsx` (credential resolution, `hasValidAppCredentials`)
- `src/navigation/RootStackNavigator.tsx` (initial route)

## 15. Source Confidence

- **Explicit** — Full flow implemented in UI and bootstrap.

## 16. Acceptance Criteria

- Given the user opens AppCredentials with empty storage,
- When they enter valid app id, auth key, and region and continue,
- Then credentials are saved to AsyncStorage and CometChat is re-initialized.

- Given stored credentials exist,
- When AppCredentials loads,
- Then fields are pre-populated from storage.

- Given `hasValidAppCredentials` is false on app start,
- When the navigator renders,
- Then the initial route is AppCredentials (see `RootStackNavigator`).
