# Editorial style notes (thesis drafts)

These notes keep **undergraduate final-year** prose consistent across [`../`](../README.md) chapter drafts.

## Variety

- **English:** **British** spelling and vocabulary for body text (e.g. *behaviour*, *formalise*, *prioritisation*, *organisation*). **Exceptions:** proper nouns, vendor/API names, and quoted code paths (e.g. `color` in JSON) stay as in source.
- **Person:** Prefer **third person** (*the project*, *the report*, *the application*) over *we* / *I* unless your faculty explicitly allows first person.

## Fixed terms

| Use | Avoid |
|-----|--------|
| **Secure Chat Application** (title case when naming the product) | Vague *the app* in formal sections |
| **FR-xxx** / **NFR-xxx** (hyphen, leading zeros as in tables) | Inconsistent IDs |
| **CometChat**, **Expo**, **React Native** (vendor/product casing) | Lowercase generic misuse |
| [`repository root`](../../../) | Inconsistent path wording |

## Incomplete work

Chapters drafted **before** final evaluation may use **will**, **to be determined**, or **conditional** wording. Do **not** change those to past tense unless the underlying work is finished and the chapter is being updated for submission.

## Hyphenation (common)

- *end-to-end* (adjective before noun)
- *cross-platform*, *real-time* (adjectives)
- *stakeholder-led*, *vendor-mediated* where used as compounds

## Cross-references

Refer to other chapters by **number** (*Chapter 4*, *§7.4*) and link to repository files where helpful. Avoid *above/below* unless the PDF order is fixed.
