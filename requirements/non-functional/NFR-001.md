# NFR-001: Cross-platform deployment

## 1. Requirement Statement

The Secure Chat Application shall be deployable as native iOS and Android applications using Expo with a development client and shared TypeScript/React Native codebase.

## 2. Requirement Type

- Non-Functional Requirement

## 3. NFR Category

- Portability

## 4. Description

The project targets both mobile platforms through React Native 0.81 and Expo SDK 54 (`package.json`, `app.json`). Native modules (Firebase, CallKeep, camera, WebRTC) require a **custom dev client** (`expo-dev-client`) rather than Expo Go alone. Bundle identifiers and package names are set per platform in `app.json`.

## 5. Rationale

Cross-platform delivery reduces duplicate business logic and matches the repository’s stated goal of iOS and Android support.

## 6. Quality Scenario

- **Source**: Engineering team.
- **Stimulus**: Need to ship one chat client on iOS and Android.
- **Artifact**: Secure Chat Application codebase.
- **Environment**: Developer machines with Xcode/Android Studio.
- **Response**: Single codebase builds two platform binaries.
- **Response Measure**: Successful `expo run:ios` / `expo run:android` per README instructions.

## 7. Measurable Criteria

- `package.json` lists `react-native` and `expo` with aligned versions.
- `app.json` defines `ios.bundleIdentifier` and `android.package`.

## 8. Applicability

- Entire application; native folders generated per prebuild (not all committed per `.gitignore` patterns).

## 9. Constraints / Policies

- New Architecture enabled in `app.json` (`newArchEnabled: true`), affecting native module compatibility.

## 10. Evidence from Repository

- `package.json`
- `app.json`
- `README.md`

## 11. Source Confidence

- **Explicit** — Declared in manifests and docs.

## 12. Verification Approach

- Inspect manifests; attempt local builds per README (manual).

## 13. Risks if Unmet

- Inability to deliver on one platform blocks user reach and graduation demo scope.
