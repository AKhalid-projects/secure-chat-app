# FR-005: QR configuration import

## 1. Requirement Statement

The Secure Chat Application shall capture QR codes using the device camera, retrieve builder configuration data from a remote API, persist the result to local storage, and update the global configuration store so the application behavior and styling reflect the imported configuration.

## 2. Requirement Type

- Functional Requirement

## 3. Module / Domain

- Configuration

## 4. Description

The `QRScreen` uses `react-native-vision-camera` with a code scanner. When a code is scanned, the app fetches configuration data (implementation includes API interaction and loading state), then `AsyncStorage.setItem('@app_config', ...)` and `useConfigStore.setState` update the in-memory builder configuration. This enables syncing the app with a CometChat builder or similar backend without manual entry of every field.

## 5. Rationale

Supports rapid alignment between a hosted builder dashboard and the mobile client.

## 6. Inputs

- Scanned QR payload string.
- Camera permission grant.

## 7. Processing / Behavior

1. Request camera permission; show scanner UI.
2. On scan, debounce duplicate scans; call remote fetch.
3. Persist response to `@app_config`.
4. Update Zustand store so UI reflects new settings.

## 8. Outputs

- Updated AsyncStorage and config store.
- User may proceed with app reflecting new config (per navigation flow in screen).

## 9. Preconditions

- Vision Camera device available; network for API call.

## 10. Postconditions

- Stored config matches fetched API data structure expected by `store.ts`.

## 11. Error Handling / Exceptions

- Alerts and loading states; errors logged (see `qr_screen.tsx` implementation).

## 12. Business Rules / Constraints

- Minimum loading time constant (`MINIMUM_LOADING_TIME`) enforces UX timing.

## 13. Dependencies

- `react-native-vision-camera`, `AsyncStorage`, `useConfigStore`.

## 14. Evidence from Repository

- `src/components/conversations/screens/qr_screen.tsx`
- `src/config/store.ts` (storage key compatibility)

## 15. Source Confidence

- **Explicit** — Full screen and persistence integration.

## 16. Acceptance Criteria

- Given camera permission,
- When a valid QR triggers a successful API response,
- Then `@app_config` is persisted and the config store updates.

- Given stored config from QR,
- When the app restarts,
- Then `initializeConfig` loads persisted builder settings (see `store.ts`).
