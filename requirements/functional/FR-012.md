# FR-012: Call history and ongoing session

## 1. Requirement Statement

The Secure Chat Application shall present call history and call detail views and shall allow users to enter an ongoing call screen for active voice or video sessions managed by CometChat.

## 2. Requirement Type

- Functional Requirement

## 3. Module / Domain

- Calls

## 4. Description

`Calls` (call logs tab) and `CallDetails` show historical call records. `OngoingCallScreen` hosts the active call session UI after accept or resume. These integrate with CometChat Calls SDK and WebRTC stack declared in dependencies.

## 5. Rationale

Voice and video are core features documented in README and config `callFeatures`.

## 6. Inputs

- Call session id, call type, or call object from navigation params.
- Active call from CometChat SDK.

## 7. Processing / Behavior

1. Display call logs; drill into detail.
2. Navigate to `OngoingCallScreen` when a call is active or resumed.

## 8. Outputs

- User sees media session UI; call state synchronized with SDK.

## 9. Preconditions

- Valid CometChat session; call permissions granted.

## 10. Postconditions

- User is in or leaves call UI consistent with SDK.

## 11. Error Handling / Exceptions

- Session errors handled in screen/helper; see `VoipNotificationHandler` for edge cases.

## 12. Business Rules / Constraints

- Call types supported per CometChat and `callFeatures` flags.

## 13. Dependencies

- `@cometchat/calls-sdk-react-native`, `react-native-webrtc`, navigation.

## 14. Evidence from Repository

- `src/components/calls/Calls.tsx`
- `src/components/calls/CallDetails.tsx`
- `src/components/conversations/screens/OngoingCallScreen.tsx`
- `src/navigation/RootStackNavigator.tsx`

## 15. Source Confidence

- **Explicit** — Screens and routes exist.

## 16. Acceptance Criteria

- Given completed calls in the account,
- When the user opens the Calls tab,
- Then call history is visible.

- Given an active session id,
- When `OngoingCallScreen` mounts,
- Then the ongoing call UI is presented.
