# FR-014: Native call UI and VoIP lifecycle

## 1. Requirement Statement

The Secure Chat Application shall integrate native call presentation through react-native-callkeep, initialize VoIP notification handling, and coordinate Android foreground service channels and iOS VoIP push registration hooks so that calls can be presented and answered in platform-consistent ways.

## 2. Requirement Type

- Functional Requirement

## 3. Module / Domain

- Calls
- Platform integration

## 4. Description

`VoipNotificationHandler` encapsulates RNCallKeep setup, permissions, Notifee channels on Android, event listeners for answer/end, and navigation to `OngoingCallScreen`. `App.tsx` initializes the handler after login (iOS immediately; Android delayed), registers VoIP token listeners, and coordinates `RNCallKeep` with incoming call UI. `PendingCallManager` stores answered-call metadata for resume after app foregrounding.

## 5. Rationale

Mobile OSes require native call UI and VoIP push for reliable incoming call UX.

## 6. Inputs

- VoIP tokens, FCM call payloads, user login state.

## 7. Processing / Behavior

1. `voipHandler.initialize()` sets up CallKeep and listeners.
2. iOS VoIP register event forwards token to CometChat helper.
3. Android background FCM `type === 'call'` branches invoke handler (`index.js`).

## 8. Outputs

- Native call UI displays; user can answer/end; app navigates to ongoing screen when appropriate.

## 9. Preconditions

- Permissions granted; dev client build with native modules.

## 10. Postconditions

- Call UUID and SDK session aligned per handler state.

## 11. Error Handling / Exceptions

- Initialization guarded; errors logged; `pendingAcceptance` paths for login delays.

## 12. Business Rules / Constraints

- CallKeep options include app name and Android foreground service channel identifiers.

## 13. Dependencies

- `react-native-callkeep`, `react-native-voip-push-notification`, `@notifee/react-native`, CometChat Calls SDK.

## 14. Evidence from Repository

## 15. Source Confidence

- **Explicit** — Large dedicated module and entry hooks.

## 16. Acceptance Criteria

- Given a logged-in user on iOS,
- When VoIP token registers,
- Then handler processes token via `handleIosVoipToken` path.

- Given an Android FCM call `initiated` payload in background,
- When the background handler runs,
- Then `voipHandler.displayCallAndroid` is invoked.
