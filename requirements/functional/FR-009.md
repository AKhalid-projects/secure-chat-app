# FR-009: Message search

## 1. Requirement Statement

The Secure Chat Application shall allow users to search messages within a conversation context and to navigate from search results or threaded hits back into the main message or thread views.

## 2. Requirement Type

- Functional Requirement

## 3. Module / Domain

- Messaging

## 4. Description

`SearchMessages` provides search UI over the CometChat SDK. When a result is selected, navigation uses `navigate` to `Messages` or `ThreadView` with parameters such as `searchKeyword`, `messageId`, `parentMessageId`, or `highlightMessageId` to restore context.

## 5. Rationale

Search supports discoverability in long conversations and is listed in product README features.

## 6. Inputs

- Active user or group context.
- Search query string from user.

## 7. Processing / Behavior

1. User enters search terms.
2. SDK/UI lists matching messages.
3. Selection triggers navigation with serialized params.

## 8. Outputs

- Focused message list or thread with highlighted target.

## 9. Preconditions

- User logged in; valid conversation context.

## 10. Postconditions

- User lands on message or thread with search context applied.

## 11. Error Handling / Exceptions

- Empty results handled in UI; errors logged.

## 12. Business Rules / Constraints

- Search scope is conversation-bound as implemented in screen.

## 13. Dependencies

- `@react-navigation/native`, CometChat SDK search APIs.

## 14. Evidence from Repository

- `src/components/conversations/screens/SearchMessages.tsx`
- `src/components/conversations/screens/Messages.tsx` (navigation to search)

## 15. Source Confidence

- **Explicit** — Full screen and navigation wiring.

## 16. Acceptance Criteria

- Given a conversation,
- When the user opens search and submits a query,
- Then results are listed per SDK behavior.

- Given the user selects a result that belongs to a thread,
- When navigation triggers,
- Then `ThreadView` or `Messages` opens with appropriate params.
