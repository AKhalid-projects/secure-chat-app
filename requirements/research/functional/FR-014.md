# FR-014: Native call UI and VoIP lifecycle

The Secure Chat Application shall integrate native call presentation through react-native-callkeep, initialise VoIP notification handling, and coordinate Android foreground service channels and iOS VoIP push registration hooks so that calls can be presented and answered in platform-consistent ways. Priority is **High**; domain spans **calls** and **platform integration**. Stakeholder discussion acknowledged that mobile operating systems impose expectations on call presentation that pure in-app overlays cannot fully satisfy.

A dedicated handler encapsulates setup, permissions, and event listeners; background message entry points on Android interact with call-related payloads. Pending-call metadata supports resuming after native answer flows when the JavaScript layer becomes ready.

Evidence appears in the VoIP handler module, pending-call utilities, application shell, and entry script. Confidence is **explicit** given the breadth of integration code. Verification is device-heavy and should be reported with limitations where simulators or accounts restrict full exercise.

**FR-012**, **FR-013**, **FR-015**, and **FR-016** interlock; **NFR-009** addresses native capability declarations.
