# FR-011: Group management and moderation

## 1. Requirement Statement

The Secure Chat Application shall provide screens to create and join groups, view group information, manage members, transfer ownership, and manage banned members in accordance with CometChat group capabilities exposed by the UI.

## 2. Requirement Type

- Functional Requirement

## 3. Module / Domain

- Group management

## 4. Description

`Groups` lists and creates groups. Dedicated screens (`GroupInfo`, `AddMember`, `ViewMembers`, `TransferOwnership`, `BannedMember`) implement administrative flows. Navigation receives `CometChat.Group` objects. Behavior aligns with builder flags such as `createGroup`, `banUsers`, `promoteDemoteMembers`.

## 5. Rationale

Group chat and moderation are core requirements for team communication.

## 6. Inputs

- Group entities from SDK; user actions on management screens.

## 7. Processing / Behavior

1. List/create/join groups.
2. Open group info, add members, view roster.
3. Transfer ownership or ban members per UI flows.

## 8. Outputs

- Updated group state on server via SDK calls.

## 9. Preconditions

- Logged-in user with appropriate group role for restricted actions.

## 10. Postconditions

- Group membership and metadata reflect successful operations.

## 11. Error Handling / Exceptions

- SDK errors surfaced per helper patterns; see `GroupHelper` and screens.

## 12. Business Rules / Constraints

- Role-based permissions enforced by CometChat server; client exposes UI.

## 13. Dependencies

- CometChat SDK group APIs, UIKit.

## 16. Acceptance Criteria

- Given the Groups tab,
- When the user creates a group,
- Then the new group appears and can be opened.

- Given a group with admin rights,
- When the user opens GroupInfo and AddMember,
- Then they can invite members per SDK rules.
