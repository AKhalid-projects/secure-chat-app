# FR-015: Push token registration

## 1. Requirement Statement

The Secure Chat Application shall obtain device push tokens (FCM on Android, APNs and VoIP on iOS) and register them with CometChat using configured push provider identifiers and helper routines.

## 2. Requirement Type

- Functional Requirement

## 3. Module / Domain

- Notifications

## 4. Description

`PushNotification.tsx` exposes `registerPushToken`. `App.tsx` coordinates FCM token refresh and initial registration after login on Android; iOS registers APNs via `PushNotificationIOS` and VoIP via `VoipPushNotification`, calling `handleIosApnsToken` and `handleIosVoipToken` from `helper.ts`. `AppConstants` supplies `fcmProviderId` and `apnsProviderId` placeholders.

## 5. Rationale

Push tokens bind the device to CometChat’s notification delivery for messages and calls.

## 6. Inputs

- Firebase/Apple device tokens, provider IDs from constants, login state flags.

## 7. Processing / Behavior

1. Request permissions on iOS.
2. On token events, call CometChat registration APIs via helpers.
3. Refresh FCM token and re-register when changed.

## 8. Outputs

- CometChat associates device with user session for push.

## 9. Preconditions

- User logged in for some registration paths; Firebase configured on device.

## 10. Postconditions

- `isTokenRegistered` state may reflect successful registration on Android path.

## 11. Error Handling / Exceptions

- Errors logged in token refresh handlers.

## 12. Business Rules / Constraints

- Provider IDs must match CometChat dashboard configuration.

## 13. Dependencies

- `@react-native-firebase/messaging`, `@react-native-community/push-notification-ios`, `react-native-voip-push-notification`, CometChat SDK.

## 14. Evidence from Repository

- `src/utils/PushNotification.tsx`
- `src/utils/helper.ts`
- `App.tsx` (token effects)
- `src/utils/AppConstants.tsx`

## 15. Source Confidence

- **Explicit** — Registration flows are implemented.

## 16. Acceptance Criteria

- Given a logged-in user on Android,
- When FCM token is obtained,
- Then `registerPushToken` is invoked with appropriate flags.

- Given iOS APNs token event,
- When handler runs,
- Then VoIP registration is triggered and APNs token forwarded per helper.
