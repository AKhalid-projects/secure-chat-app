# FR-016: Notifications and deep linking

## 1. Requirement Statement

The Secure Chat Application shall display local notifications for incoming messages when appropriate, handle foreground and background notification interactions, and navigate users to the relevant conversation or thread using payload data on Android and iOS.

## 2. Requirement Type

- Functional Requirement

## 3. Module / Domain

- Notifications

## 4. Description

**Android**: `messaging().onMessage` shows Notifee notifications via `displayLocalNotification`, considering `activeChat` to suppress duplicates. Notifee foreground and background press handlers parse `data` and call `navigateToConversation` or dispatch stack actions with `userUid`, `groupGuid`, `parentMessageId`. Initial notification opens app to conversation. **iOS**: `checkInitialNotificationIOS`, `onRemoteNotificationIOS` handle remote payloads. **Shared**: `NavigationService` queues navigation if not ready. `index.js` registers Notifee background event handler and FCM background handler for non-call and call branches.

## 5. Rationale

Users must return to the right chat from push without losing context.

## 6. Inputs

- FCM/APNs remote messages, Notifee events, active chat id from context.

## 7. Processing / Behavior

1. Show or suppress local notification.
2. On tap, parse `receiverType`, `conversationId`, `sender`, `parentId`.
3. Navigate to `Messages` or thread with extracted ids.

## 8. Outputs

- User lands on target screen; notifications may be cancelled.

## 9. Preconditions

- Push permissions; valid payload schema from CometChat/Firebase.

## 10. Postconditions

- Navigation stack reflects deep link target.

## 11. Error Handling / Exceptions

- Try/catch around handlers; logs on failure.

## 12. Business Rules / Constraints

- Group conversation id parsing uses string split logic in background handler.

## 13. Dependencies

- `@notifee/react-native`, `@react-native-firebase/messaging`, `ActiveChatContext`, `NavigationService`.

## 15. Source Confidence

- **Explicit** — End-to-end handlers implemented.

## 16. Acceptance Criteria

- Given Android foreground message and no matching active chat,
- When FCM delivers payload,
- Then a local notification is displayed.

- Given user taps a Notifee notification with user receiver type,
- When handler runs,
- Then navigation opens Messages with `userUid` from payload.

- Given navigation ref not ready,
- When `navigate` is called,
- Then pending navigation executes on `onReady`.
