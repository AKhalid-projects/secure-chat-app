# FR-003: UID-based user login

## 1. Requirement Statement

The Secure Chat Application shall authenticate end users by CometChat user identifier (UID) using `CometChatUIKit.login`, and upon success shall navigate to the primary tabbed experience.

## 2. Requirement Type

- Functional Requirement

## 3. Module / Domain

- Authentication

## 4. Description

After tenant credentials are configured, the user selects a sample user or enters a UID manually. The UI calls `CometChatUIKit.login({ uid })`, then navigates to `BottomTabNavigator` and resets the navigation stack to that route. This establishes the CometChat session for messaging, calls, and push token registration.

## 5. Rationale

CometChat’s model uses UID-based auth for this sample; it supports quick testing without a custom identity provider in-app.

## 6. Inputs

- Selected sample user UID or manually typed UID string.
- Preloaded CometChat SDK from successful init.

## 7. Processing / Behavior

1. Optionally load sample users from bundled JSON.
2. On continue, call `CometChatUIKit.login({ uid })`.
3. Navigate to `BottomTabNavigator` and reset navigation state.

## 8. Outputs

- Active CometChat session for the UID.
- `loginSuccess` on login listener (see `App.tsx`).

## 9. Preconditions

- Valid app credentials and successful SDK init.

## 10. Postconditions

- User is logged in; `userLoggedIn` state updates via `LoginListener`.

## 11. Error Handling / Exceptions

- Login failures logged; loading state cleared.

## 12. Business Rules / Constraints

- Either selection or manual UID must be provided before continue.

## 13. Dependencies

- `CometChatUIKit`, `sampledata.json`, `navigationRef`.

## 14. Evidence from Repository

- `src/components/login/SampleUser.tsx`
- `App.tsx` (`CometChat.addLoginListener`)

## 15. Source Confidence

- **Explicit** — Login flow is explicit in code.

## 16. Acceptance Criteria

- Given a valid UID and working SDK,
- When the user taps continue,
- Then `CometChatUIKit.login` is invoked with that UID and navigation moves to the main tabs.

- Given login succeeds,
- When `loginSuccess` fires,
- Then `userLoggedIn` becomes true in the app shell.
