# FR-011: Group management and moderation

The Secure Chat Application shall provide screens to create and join groups, view group information, manage members, transfer ownership, and manage banned members in line with CometChat group capabilities exposed by the user interface. Priority is **Medium**; domain is **group management**. Workshops treated group collaboration as a core expectation alongside direct messaging, though administrative depth remains bounded by SDK roles and project time.

Multiple screens participate in this obligation, each receiving group context through navigation. Configuration flags in JSON settings document intended feature toggles at a product level; the client implements corresponding routes when enabled.

Evidence is spread across grouped screen modules and group list behaviour. Confidence is **explicit** for registered routes and screens. Verification should respect role constraints enforced server-side, which the client surfaces but does not replace.

**FR-007** connects group messaging; **FR-004** may influence which group features are emphasised in configuration.
